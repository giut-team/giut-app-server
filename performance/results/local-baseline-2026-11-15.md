# 팀·채팅 API 개선 전 성능 기준선

측정일: 2026-11-15  
상태: **로컬 H2 기준 측정 완료 — MySQL 운영 유사 환경 재측정 필요**

## 측정 목적

팀·채팅 조회 API의 N+1 쿼리와 반복 조회를 개선하기 전에 SQL 실행 횟수와 HTTP 응답
성능을 기록했습니다. 이후 동일한 데이터와 부하 조건으로 다시 측정하여 개선 효과를
비교했습니다.

## 측정 환경

- 애플리케이션: Spring Boot 4.1.1
- 런타임: Java 21
- 부하 도구: k6 2.4.0
- 데이터베이스: H2 인메모리 DB, MySQL 호환 모드
- 실행 위치: 개발자 로컬 Mac
- 가상 사용자: 10명
- API별 부하 시간: 증가 5초 + 고정 부하 15초 + 감소 2초 = 22초
- 요청 방식: think time 없이 연속 GET 요청
- 전체 k6 통합 테스트 실행 시간: 1분 35초

> H2 인메모리 DB는 네트워크 지연과 MySQL 실행 비용이 없어 절대 성능이 실제 운영보다 높게
> 측정됩니다. 아래 결과는 코드 변경 전후를 비교하기 위한 수치입니다. 최종 포트폴리오에는
> 같은 스크립트를 MySQL 성능 DB와 고정된 서버 사양에서 다시 실행한 결과를 사용합니다.

## 데이터 규모

### SQL 실행 횟수 측정

- 팀 12개
- 팀별 활성 팀원 5명
- 팀별 지원 4개
- 개인 채팅방 10개
- 채팅방별 메시지 40개

### k6 HTTP 측정

- 팀 100개
- 팀별 활성 팀원 5명
- 팀별 지원 10개
- 개인 채팅방 50개
- 채팅방별 메시지 200개
- 전체 메시지 10,000개

## SQL 실행 횟수 기준선

| API | SQL 문장 수 | Hibernate 쿼리 수 | 서비스 처리 시간 |
|---|---:|---:|---:|
| `GET /api/teams` | 13회 | 13회 | 3.824 ms |
| `GET /api/teams/{teamId}` | 7회 | 6회 | 2.052 ms |
| `GET /api/chat-rooms` | 41회 | 31회 | 8.092 ms |
| `GET /api/chat-rooms/{chatRoomId}/messages` | 5회 | 4회 | 1.861 ms |

### 해석

- 채팅방 목록은 채팅방 10개를 조회할 때 SQL이 41회 실행되어 반복 조회 문제가 가장 크게
  나타났습니다.
- 팀 목록도 한 페이지 조회에 SQL 13회가 실행되어 팀원 수·모집 분야·북마크 등의 일괄
  조회가 필요합니다.
- 메시지 목록은 SQL 수가 상대적으로 적지만 데이터가 증가할 때를 대비해 커서 조회용
  인덱스의 실행 계획을 별도로 확인해야 합니다.

## 후속 개선 목표

1. 팀 목록의 팀원 수·모집 분야·북마크 여부를 집계 쿼리 또는 DTO Projection으로 조회합니다.
2. 메시지 커서 조회 쿼리의 인덱스 사용 여부를 `EXPLAIN ANALYZE`로 확인합니다.
3. 개선 후 동일한 SQL 테스트와 k6 테스트를 다시 실행합니다.
4. SQL 실행 횟수와 p95 응답 시간을 개선 전후 표로 비교합니다.
5. 로컬 비교가 끝나면 MySQL 전용 성능 DB에서 최종 성능을 측정합니다.

## 채팅방 목록 N+1 개선 결과

채팅방마다 채팅방 엔티티, 상대방, 차단 관계를 개별 조회하던 로직을 제거했습니다. 현재 사용자의
활성 개인 채팅방, 상대 사용자 ID, 양방향 차단 여부를 projection 쿼리 한 번으로 조회하도록
변경했습니다. API 응답 형식과 기존 차단 정책은 그대로 유지했습니다.

| 항목 | 개선 전 | 개선 후 | 변화 |
|---|---:|---:|---:|
| SQL 실행 횟수 | 41회 | 1회 | 97.6% 감소 |
| 전체 요청 수 | 65,998건 | 341,104건 | 416.8% 증가 |
| 처리량 | 2,999.805 req/s | 15,504.645 req/s | 416.9% 증가, 약 5.17배 |
| 평균 응답 시간 | 3.137 ms | 0.590 ms | 81.2% 감소 |
| p95 응답 시간 | 5.474 ms | 1.208 ms | 77.9% 감소 |
| p99 응답 시간 | 8.596 ms | 2.215 ms | 74.2% 감소 |
| 요청 실패율 | 0.000% | 0.000% | 실패 없음 유지 |

### 검증 내용

- 활성 개인 채팅방과 상대 사용자 ID가 기존과 동일하게 반환되는지 확인했습니다.
- 어느 한쪽이 차단한 채팅방이 양쪽 목록에서 제외되는지 확인했습니다.
- 차단 해제 후 기존 채팅방과 메시지가 다시 노출되는지 확인했습니다.
- 채팅방이 10개여도 목록 조회 SQL이 1회만 실행되는지 자동 테스트로 검증했습니다.
- 동일한 10 VU, API별 22초 조건으로 개선 전후 k6 결과를 비교했습니다.

> 응답 시간과 처리량 개선율은 H2 로컬 환경에서 측정한 결과입니다. 쿼리 수 감소는 구조적인
> 개선 결과지만, 실제 운영 환경의 개선율은 MySQL/RDS 환경에서 다시 검증해야 합니다.
